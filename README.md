# 听屿 FM

手机和电脑使用同一套 React + TypeScript + Vite + Zustand 网页代码。

- [当前 Vercel 站点](https://folia-major-ai-radio-preview.vercel.app/)：已部署前端与内置 QQ 后端。
- [GitHub Pages 预览](https://xiaotong123520.github.io/folia-major/)：静态前端；更新以 Pages 工作流成功为准，推送源码不等于该地址已更新。

右上角「听屿 FM」菜单包含音乐文件导入、分享链接解析、电台与 Apple Music 官方授权。可将网页添加到手机主屏幕作为 PWA 使用。

手机与桌面共用原有首页、曲库、队列、播放器、歌词样式和设置页面。窄屏通过同一组件的布局适配，不再覆盖独立手机首页。「听屿 FM」工具菜单在两端都能打开服务器曲库及原有统一登录窗口。

网页版扫码登录需配置真实的平台后端。Pages 构建读取仓库 Actions Variables 中的 `VITE_NETEASE_API_BASE`、`VITE_QQ_API_BASE`、`VITE_KUGOU_API_BASE`，分别填写对应服务的公开 HTTPS 根地址后重新发布。外部点歌接口不属于平台账户登录后端，且可用性与内容授权尚未经过验证。各平台可用登录方式由现有登录窗口显示；同一手机能否识别二维码取决于平台 App 支持。未配置后端时不能完成扫码登录。

## 当前能力

截至 2026-10-24：服务器来源已在浏览器实测音频加载和播放进度持续前进；用户已确认网易云与 QQ 音乐均可扫码登录，并能在授权后正常播放歌曲。平台登录与播放结果由用户确认；服务器来源的播放另外经过浏览器实测。真实 iPhone 的主屏幕模式、横屏和后台播放仍需实机确认。

- 本地音频：通过普通文件选择器导入，兼容没有文件夹访问 API 的手机浏览器；使用原生音频控件播放。
- 刷新恢复：音频字节和网络直链保存在当前浏览器的 IndexedDB，重新打开后恢复队列，不会恢复已经失效的 blob URL。浏览器空间不足时显示提示。不会上传文件。
- 手机与电脑布局：同一版本、同一套原有页面和播放器。窄屏曲库使用双列卡片，菜单、弹窗和播放器按可用宽度排版。
- 平台登录：手机与电脑复用同一个账户 controller 和登录窗口，支持平台实际提供的二维码/浏览器登录；QQ 等平台仍需要对应后端，显示入口不等于已经完成登录。外部点歌来源与账户登录独立，使用前必须核实平台授权与服务条款。
- 分享链接：识别平台与歌曲 ID，经 Omni 读取曲目；可选后端按原平台 + 精确 ID 兜底，不按标题自动替换其他录音。
- 服务器音乐：可选只读网关和 Omni 适配器，支持搜索、歌词与 Range 音频流；需配置你自己的真实服务。

本地文件仅保存在导入它的浏览器，**不会自动出现在另一台设备**。两端共享曲库请配置 Navidrome 或服务器音乐源。清除浏览器数据会移除本地导入缓存，需保留原文件。网络直链也可能过期。

## 自有服务器解析兜底

可选音乐曲库仅应接入由你持有传播许可或明确获授权提供公开在线播放的内容。公开仓库不列出第三方媒体目录、歌曲清单或音频流请求路径；播放器中的任何来源也不因此取得访问或传播授权。第三方平台登录仍需独立且符合平台规则的后端。

音频 `Range / 206`、跨域响应和浏览器解码仍需按合法授权的测试文件逐一验证；已能播放不代表拥有公开传播权。原服务的访问权限和可用性仍然生效。

见 [服务器接入与验收](docs/personal-deployment.md)；如需播放你服务器上已经保存的合法音乐文件，另见 [宝塔 PHP 本地曲库接口](deploy/php-music-api/README.md)。该接口不会移动或修改原歌曲。GitHub Pages 只托管前端，无法运行 PHP/Node、保存平台会话或提供服务器音频代理。尚未配置 API 地址时，界面明确显示服务器未连接。

## 服务器专辑与电台封面墙

「听屿 FM」工具菜单 →「服务器专辑封面墙」进入原有专辑页面，展示公开目录快照中的 43 张专辑、642 首歌曲；无需虚构平台登录。手机使用原页面的双列卡片，电脑保留原布局。

AI 电台同时查询服务器目录与当前平台，仍通过 Omni 播放。没有匹配时明确提示并展示服务器曲目供选择。点击「保存到封面墙」后，在「我的电台封面墙」打开歌曲集合，封面、歌词和播放均复用主播放器。默认还提供整个服务器目录的电台卡片。

电台保存的是歌曲来源和元数据，音频继续走原地址，不复制服务器文件。保存仅在当前浏览器保留（最多 24 个电台、每台最多 80 首在线歌曲），不会跨设备同步；本地文件和 Navidrome 曲目不包含在保存中。浏览器存储失败会提示，其他平台歌曲打开时按原平台及精确 ID 重新读取元数据；仍需对应平台的真实服务和访问权限。

## 手机封面墙

手机首次进入资料库时，保存的 Bravais 桌面墙面偏好会在本次会话回退为 Grid，不覆盖保存值。切换音乐源后，若当前分类不受支持，会优先进入可用的专辑分类，避免停在空歌单页。新部署可用 `VITE_INITIAL_ONLINE_PROVIDER=hearttrace` 设置首次访问来源，已有平台选择优先；`VITE_LIBRARY_INITIAL_SUITE=grid` 设置无保存偏好时的初始界面。

窄屏下资料库墙与队列拼贴使用普通页面切换，避免翻牌交接时同时保留两面墙；两种墙减少屏幕外的封面预渲染。手机资料库显示期间卸载墙后的歌词动画，返回播放页时恢复；音频播放不受影响。触摸设备不使用封面悬停滤镜，工具菜单为底部播放卡片和进度条留出空间。歌词与两种墙的导航功能仍保留。Safari 的进程内存限制需在真实 iPhone 上验证。

## 添加到主屏幕与尺寸适配

iPhone 在 Safari 打开站点，通过「分享 → 添加到主屏幕」安装。主屏幕入口与 Safari、Vercel 与 Pages 可能使用不同的本地数据和登录状态；一个入口登录成功，不代表其他入口已登录。

- 手机网页容器使用动态视口高度，预留顶部状态栏、底部手势条以及横屏左右安全区。
- 浮动控件以安全区内的容器定位，避免重复计算边距；本地播放器与工具菜单限制高度并支持内部滚动。
- 手机输入框至少 16px，减少聚焦搜索框时 Safari 自动放大页面。
- 更新后先关闭主屏幕应用，再联网重新打开，让自动更新的 Service Worker 获取新版。若仍是旧版，可先用 Safari 打开同一地址刷新；不要通过清空网站数据更新，以免丢失本地导入和保存内容。

适配实现见 `src/components/app/AppShell.tsx`、`src/index.css`、`src/components/app/PersonalMusicTools.tsx` 和 `src/components/app/ImportedAudioPlayer.tsx`。类型检查和生产构建已通过；不能据此认定真实 iPhone 的尺寸验收已完成。

## 手机音频缓冲（2026-10-25）

完整媒体缓存优先；未命中时，手机触摸设备会对不超过 15 分钟的在线音乐尝试播放前完整缓冲，最多 24 MiB、等待 30 秒。完成后用本地 Blob 播放，减少边听边加载造成的断续。首次播放可能需要等待缓冲；超时、跨域限制、试听片段、大文件及长播客保留原流播放，不降低音质。

仅 HTTP 200 的完整音频下载可进入缓冲；206 片段、文本错误页、长度不符或中断的下载均不作为整首歌使用。开启媒体缓存时，把本次下载的同一份完整字节经原有整曲校验后保存，并记录音质与 ReplayGain；缓存关闭或写入失败时仍可用临时缓冲播放。换歌会取消已失效的读取，故障恢复路径跳过预缓冲以免重复等候；自动混音交接保留已预热的流，不在交接时重复下载。缓存是否命中取决于当前设备、浏览器及缓存设置，不表示每首歌都已存好。

服务器授权网关保留票据校验与 Range/206，并改用 `read1` 立即转发可用字节；没有修改原音源网站或平台登录。分段、长度、下载上限、超时、回退及缓存写入有自动测试；真实 iPhone 的连续播放仍需验收。

## 手机后台播放

支持 Audio Session API 的浏览器会在播放前声明 `playback` 音频会话。回到前台时，若音频元素仍在播放但 Web Audio 处于 `suspended` / `interrupted`，尝试恢复音频图；不会重新调用音频元素的 `play()`，因此不会覆盖手动暂停或锁屏暂停。

切后台与锁屏仍受 iOS / 浏览器版本、系统中断和内置浏览器策略影响，需要在真实手机验证。关闭网页或强制结束浏览器后，网页播放器无法继续运行；添加到主屏幕也不等于原生 App 的后台音频服务。

## 宝塔视频库（可选）

听屿 FM现在可以使用 **GitHub Pages 托管的手机 / 电脑前端 + 宝塔 PHP 视频上传服务**。网页菜单中「视频库」负责视频浏览和原生 HTML5 播放；「管理员上传视频」打开服务器独立的 HTTPS 后台，在 iPhone、安卓或电脑选取 MP4 / WebM / MOV 上传。推荐 H.264/AAC 的 MP4 以获得最好的兼容性。

服务器原始视频存储在宝塔**网站根目录外**，不会提交到 GitHub，也不会移动原音乐文件。播放 API 支持 Range/206 拖动进度。默认是**禁用公众访问**：只对有公开传播授权的视频，在管理员确认后开启 `public_gallery=true`。这是公开视频库，不是仅自己可见的私有鉴权影院。

部署步骤与安全细节见 [宝塔 PHP 视频服务文档](deploy/php-video-api/README.md)。GitHub Actions Variables 变量 `VITE_TONGSHENG_VIDEO_API_URL` 应填成服务器的 HTTPS `index.php` 地址，不能包含密码或私钥。只更新前端并不会把 PHP 服务部署到你的实际服务器。
